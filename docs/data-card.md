# Data card: ClaimSense decision dataset

Generated by `training/generate/decision_dataset.py` (decision-dataset-v1, scenario engine
scenarios-v1, prompt decision_v1, seed 20260921). Regenerate with
`uv run python -m training.generate.decision_dataset`. The files are written to
`data/generated/decision/` and are never committed (H9).

## Purpose

Fine-tuning and evaluating the Gemma 4 decision model (INSTRUCTIONS.md §10). Each record is a chat:
system prompt `decision_v1`, a user message with the claim, rules result, plan benefits and
retrieved coverage criteria, and the target `SLMOutput` JSON. The model never sees or produces
dollar amounts.

## Where the labels come from

- Coverage criteria: `data/curated/coverage_policies/` (each criterion cites its LCD).
- Whether a diagnosis supports a procedure: the covered ICD-10-CM groups of each policy's billing
  article (`data/curated/diagnosis_support.csv`, from the MCD download in `data/raw/mcd/`).
- Lines denied by rules: NCCI PTP v323r0, MUE (October 2026) and plan exclusions, read as in the
  golden rules assumptions (`tests/golden/README.md`).
- Clinical notes: synthetic sentences from `training/generate/templates/clinical_notes.yaml`, written
  so each criterion is met, not met or not documented. Template set A is used for train and
  validation; set B, with different wording and style, only for test.
- Patients, members and providers: `training/generate/reference.py` (Faker, fixed seed). No real data.

## Quality and leakage checks

All passed (0 problems) before the files were written:

- No claim field or clinical note contains approve, deny, reject, pend (or their forms),
  "not covered" or "medically necessary".
- Every target validates as `SLMOutput`; every rules-passed line appears exactly once; every
  criterion ID exists and was retrieved for its line; DENY and PEND lines have a reason; PEND lines
  list missing information; every benefit category is one of the line's candidates (D3).
- Train and validation contain no test-only policy, as a claim line or as a retrieved criterion.
- No test clinical note appears in train.

## Known limitations

- Retrieval is simulated until P3.3: a policy line gets its profile's criteria (at most 3,
  RAG_TOP_K) plus distractors from other policies. Regenerate after P3.3 with real retrieval.
- Group C rule outcomes come from the generator's own reading of the NCCI/MUE files and exclusions;
  compare them with the P2.3 rules engine once it exists.
- Notes come from templates, so their wording varies less than real notes; the test split's
  separate template set measures part of this.
- Colonoscopy lines are always diagnostic or surveillance (ENDOSCOPY): no source in `data/raw/`
  lists screening diagnoses for the billing article, so PREVENTIVE_CARE colonoscopy is not generated.
- Visit limits are never exceeded: no reason code is mapped for a reached benefit limit.
- Records contain CPT codes (not descriptors). Keep the files private; upload only as a private
  Kaggle dataset (SOURCES.md).
